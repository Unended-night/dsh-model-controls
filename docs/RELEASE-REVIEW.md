# 发布审核准备

当前候选版本为 **3.1.0**，展示名为 **模型请求控制 / Model Request Controls**。内部包名仍为 `dsh-llm-compat`，配置 ID 仍为 `llm-compat`。正式包名可以考虑 `dsh-model-controls`，须在确定名称和安装迁移方案后再改。

本轮已完成的检查及未验证范围见 [验收记录](VALIDATION.md)。

本轮仅准备源码、文档、配置示例、MIT 许可证、测试、CI 和本地审阅包。`private: true` 保留，没有 npm 发布流程、远程仓库地址或自动发布凭据；现有本机目录链接和 profile 安装注册保持原样。

## 审核内容

1. 核对 README 的实际功能、默认值、重试范围、超时生效时机与限制。
2. 在当前本机安装重启后检查新名称、五种身份选项、独立超时表单和持久化。
3. 审阅 `npm run pack:review` 生成的压缩包、文件清单和 SHA-256。包内应只有运行源码、语言元数据、bundle 注册、许可证、说明和示例。
4. 确认正式名称、仓库所有者、提交作者公开身份和安全报告渠道。当前 Git 作者沿用本机配置，发布前应确认是否使用公开邮箱。
5. 确定首批支持的 Harness 版本和操作系统，在干净环境验证安装、升级、卸载，再填写公开安装说明。
6. 审核通过后再修改发布开关、仓库链接、安装渠道和版本标签。

## 可复现的检查

```sh
npm ci --ignore-scripts
npm test
npx playwright install chromium
npm run test:ui
npm run check:release
npm run pack:review
```

`check:release` 检查 Git 索引中的待发布文件、必要文档、默认模式、包内容边界、个人路径和凭据形态。可通过 `--forbid <正则表达式>` 增加项目审核用词检查。请先暂存拟公开文件，使检查覆盖本次新增文件。

`.github/workflows/ci.yml` 只测试和生成审阅构件，不发布包。工作流需要推送到正式仓库后才能验证远程运行结果；本地测试成功不等于 CI 已运行。

## 本地资料与公开历史

旧的开发安装脚本、运行时副本、测试输出和桌面诊断资料保留在本机且被 Git 忽略，不进入源代码历史或分发包。清理前快照另存于仓库外的本地恢复 bundle。公开时使用清理后的分支或 `git archive` 导出的源码，不打包整个本机工作目录，也不复制本地 `.git`、reflog 或恢复备份。

## 已知边界

- 原生默认只表示保留原生 User-Agent；启用总开关时仍有统一恢复与通用请求规范化。
- 模型发现没有插件内部自动重试；宿主或 SDK 自身的行为由其配置决定。
- 本次没有改变本机安装方式，也没有提供已验证的公开下载安装命令。
- 当前自定义设置页为中文；英文元数据不代表完整英文界面。
- 全局 User-Agent/重试设置影响支持的模型请求；超时按原生渠道单独保存。
- 预设标识不能证明客户端身份、增加账户权限、修复认证或替代服务端配置。

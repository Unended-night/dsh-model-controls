# 模型请求控制 · 使用说明

在 DeepSeek Harness 中管理每个模型渠道的 User-Agent 和流空闲超时，并设置请求失败后的重试与自动继续行为。

[下载 4.0.0 安装包](https://github.com/Unended-night/dsh-model-controls/releases/download/v4.0.0/dsh-model-controls-4.0.0.tgz) · [安装与卸载](https://github.com/Unended-night/dsh-model-controls/blob/main/docs/INSTALLATION.md) · [反馈问题](https://github.com/Unended-night/dsh-model-controls/issues)

安装并启用后重启 Harness，在 **设置 → 模型请求控制** 中进行配置。平时保存设置无需重启。

## 渠道请求配置

先在上方选择一个已有模型渠道。User-Agent 和流空闲超时都只对所选渠道保存；不同渠道可以使用不同设置。即使两个渠道使用相同接口地址，也不会互相覆盖。

修改后点击 **保存渠道配置**。切换渠道会保留当前页面内的草稿，但不会自动保存；关闭页面会放弃未保存的输入。

### User-Agent

User-Agent 是请求中的客户端标识。没有特殊要求时，使用**原生（默认）**即可。

| 选项 | 请求中使用的 User-Agent |
| --- | --- |
| 原生（默认） | 保留 Harness 原有值 |
| Claude Code | `claude-cli/2.1.296 (external, sdk-cli)` |
| Codex | `codex_cli_rs/0.162.1` |
| pi | `pi (<平台> <系统版本>; <架构>)` |
| 自定义 | 使用输入的非空、单行 ASCII 文本 |

这些选项只替换 User-Agent，不附加其他客户端的专属请求头，也不改变模型地址、认证或协议。预设采用固定的标识格式，不表示启动了相应客户端或获得了额外权限。

未配置的渠道保留原生值。选项下方的说明会随选择变化；选择“自定义”后会出现输入框。

### 流空闲超时

设置连续没有收到有效输出时，最多等待多少秒。它关注文字、思考或工具调用等有效输出，只有网络心跳时仍可能超时。

- 未调整过的渠道默认 **300 秒**，即 5 分钟。
- 填写 `600` 表示允许连续等待 10 分钟。
- 可输入 0.001～2147483.647 秒；`0` 不表示关闭超时。

遇到 `pi-ai stream idle timeout after 300000ms`，表示该次调用连续 300 秒没有解析到有效输出。延长超时可以容许模型更长时间没有输出，但不能修复已经断开的连接。

保存后，后续新模型调用使用新值，正在进行的调用保持原值。此项独立于插件总开关；卸载插件后也会保留在 Harness 的渠道设置中。需要恢复默认时，填写 `300` 并保存。

## 全局失败处理

下方的恢复设置适用于所有渠道。修改后点击 **保存全局配置**；保存渠道配置不会同时提交这里的修改。

### 连续重试

模型请求失败后，按设定次数和固定间隔再次请求。默认额外重试 **5 次**，每次等待 **2 秒**。

首次请求不计入次数。设为 60 时，消息页显示 `1/60`、`2/60` 等实际进度；设为 0 时不重试。等待间隔可设置为 0.1～86400 秒。

开启**不限重试次数**后，次数上限暂不生效，进度以 `1/∞` 等形式显示，直到成功或手动停止。

### 重试耗尽后发送继续消息

先执行有限次数的重试。如果仍然失败，等待当前轮次结束且会话空闲后，发送一条可见的继续消息。

| 设置 | 默认值 | 含义 |
| --- | --- | --- |
| 最多自动继续次数 | 3 | 每条手动消息最多触发的自动继续次数；0 表示不发送 |
| 发送前等待 | 2 秒 | 发送继续消息前的等待时间，可设为 0～86400 秒 |
| 消息正文 | 请继续完成。 | 可以修改为适合当前任务的文字 |

自动消息会注明插件来源和当前次数，例如：

> 请继续完成。
>
> （模型请求控制插件自动发送：请求重试 5 次仍失败，自动继续 1/3。）

自动继续仅用于主会话。手动发送新消息或任务成功完成后，次数重新计算。手动停止、关闭插件、切换恢复模式或会话出现新的活动，都会阻止相应的待发送消息。

## 开关与选项联动

- 关闭**启用模型请求控制与统一重试**后，User-Agent 修改、插件重试和自动继续停止生效；已有数值保留，流空闲超时仍可配置。Harness 自身的恢复行为由其设置决定。
- 开启**不限重试次数**后，额外重试次数不可编辑；关闭后恢复原数值。此选项只用于连续重试模式。
- 额外重试次数为 **0** 时，重试间隔不可编辑。
- 自动继续次数为 **0** 时，发送等待时间和消息正文不可编辑。

## 保存后何时生效

| 设置 | 生效时机 |
| --- | --- |
| 渠道 User-Agent | 保存后的下一次请求 |
| 流空闲超时 | 后续新模型调用，进行中的调用保持原值 |
| 重试次数和间隔 | 下一次失败判定，已经开始的等待不重新计时 |
| 自动继续参数 | 下一次排队的自动消息；已排队的消息保留原参数 |
| 总开关与恢复模式 | 待发送的继续消息会在发送前再次检查 |

**保存不会重新启动已经失败结束的任务。** 如需继续该任务，请重新发送消息。

渠道保存可能出现部分成功，例如 User-Agent 已保存而超时保存失败。页面会明确指出失败项并保留输入，再次保存只提交尚未成功的部分。如果提示配置发生冲突，请重新打开设置，读取最新值后再修改。

## 使用范围与注意事项

适用于 Windows 上已验证的 Harness 0.2.1-rc.2，支持 OpenAI Chat Completions、OpenAI Responses 和 Anthropic Messages。当前设置页为中文，其他系统上的实际 Harness 使用尚未验证。

重试针对会话中的模型请求失败，包括连接错误和流式响应错误。读取模型列表等操作不会触发插件的会话重试或自动继续。插件还会对缺省工具参数约束和独立空流事件做通用兼容处理。

重试和自动继续可能增加请求量与费用，不能解决无效密钥、额度不足或错误的接口配置。请按服务提供方的说明在 Harness 中设置模型地址、协议和凭据。

插件不发送遥测，也不在恢复摘要中记录 API Key、模型请求正文、自定义 User-Agent 或继续消息正文。分享错误信息前，请移除个人数据。

需要手动编辑配置时，可参考 [请求控制示例](examples/request-controls.yml) 和 [超时示例](examples/stream-timeout.yml)。
